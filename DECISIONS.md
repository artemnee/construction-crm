# Решения и допущения

## Решения там, где ТЗ неоднозначно

| Вопрос | Решение |
|---|---|
| Может ли у задачи не быть исполнителя | Нет, он обязателен при создании. Исполнитель должен быть пользователем с ролью «исполнитель» (проверяет триггер). |
| Смена исполнителя | Постановщик может менять его в любом статусе, кроме «Принята». |
| Удаление объекта с задачами | Запрещено (ограничение внешнего ключа), интерфейс показывает понятное сообщение. |
| Удаление задачи | Разрешено постановщику, история задачи удаляется вместе с ней (каскад). Для аудита лучше хранить историю отдельно или запретить удаление. |
| Запись о создании в истории | При создании задачи пишется строка «— → Новая» (автор — постановщик). |
| Кто видит список пользователей | Все вошедшие читают `profiles` (имя и роль) для отображения исполнителей и авторов. Email хранится в закрытой таблице авторизации и не отдаётся. |
| Видимость объектов исполнителю | Только те, где у него есть хотя бы одна задача. |
| Может ли постановщик делать исполнительские переходы | Нет. «Взять в работу», «Отправить на проверку» и «Вернуть в работу» только у назначенного исполнителя. |
| Ответ на чужую задачу | Для исполнителя чужая задача отвечает так же, как несуществующая, чтобы не раскрывать факт её существования. |
| Комментарий | Обязателен только для «На проверке → На доработке». В остальных переходах необязателен. |
| Создание пользователей | Вручную в Supabase, плюс строка в `profiles`. Триггера на регистрацию нет. |

## Как реализована защита
- Права на колонки: у клиента нет права записи в `tasks.status`, `author_id`, `created_at`. Автор берётся из `auth.uid()`.
- Статус меняет только функция `change_task_status` (`security definer`, блокировка строки, проверка перехода и запись истории в одной транзакции).
- `task_history`: клиентам только `select`.
- Права на `anon` сняты полностью, `EXECUTE` у служебных функций закрыт.

## Что проверено
- Агент-ревьюер прогнал миграцию и seed на локальном Postgres: изоляция исполнителя, запрет прямого изменения статуса, все разрешённые и запрещённые переходы, закрытая история, права `anon`.
- `npm run build` проходит.

## Что не успели / не проверено
- Реальный вход через Supabase Auth с seed-пользователями и работа через PostgREST ещё не проверены на живом проекте.
- Автоматических тестов нет, проверка выполнена вручную SQL-сценариями.
- Интерфейс не обновляется в реальном времени, данные подгружаются при открытии страницы и после своих действий.
- Исполнитель в форме задачи выбирается по имени, различать тёзок неудобно.
- Список профилей загружается один раз после входа, изменения видны после перезагрузки.
- Бандл около 490 КБ, без разделения на части.
- Пагинации и поиска нет.
