# Мини-CRM «Объекты и задачи» — рабочий журнал

ТЗ: `TZ.md`. Стек: React + TS (Vite), Supabase (Auth + Postgres + RLS).
Журнал ведётся по ходу работы: что сделано, какие решения приняты.

## Архитектурные решения
- Роли: `profiles.role` (`manager` | `executor`). Профили создаются вручную вместе с пользователями, триггера на регистрацию нет (регистрация отключена).
- Статус задачи **нельзя** менять прямым UPDATE: у `authenticated` нет права на колонку `status`. Единственный путь — RPC `change_task_status` (security definer), которая проверяет роль, исполнителя, переход, комментарий и пишет историю в той же транзакции.
- `task_history`: клиентам только SELECT; запись только из RPC и триггера создания задачи.
- Исполнитель видит только свои задачи и объекты, где у него есть задачи (RLS).
- Во фронте только anon key. `service_role` нигде в репо.
